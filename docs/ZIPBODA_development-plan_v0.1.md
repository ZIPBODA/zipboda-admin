## 2. 개요

### 2.1 목적
집보다 **운영 관리자 콘솔(`zipboda-admin`)** 개발 계획. 요구사항·화면·API 정의서(zipboda-web 대표 관리)를 근거로 관리자 요구사항ID(REQ-AD-*)·화면ID(ZB-A-*)·관리자 API(100~199)를 추적한다.

### 2.2 서비스 개요
공공 청약 정보·평면도/3D 집구경·영감·쇼룸·가점·커뮤니티, 2차 가구 커머스. 운영 콘솔은 이 서비스의 콘텐츠·데이터·회원·주문·통계·감사를 관리한다.

### 2.3 범위 / 가정 / 저장소 매핑
관리자 화면 전체(**ZB-A-*, 19개**, 감사로그 화면 포함)와 관리자 API 소비.
> **[중요]** 관리자 화면은 Figma에 부재하여 사용자 기능에서 **도출**되었다(화면설계서 관리자용 `도출` 표기). 아래 **S0에서 화면 기획 확정을 완료해야** 후속 구현을 착수한다(검토 admin-Critical).

| 저장소 | 역할 | 비고 |
|--------|------|------|
| **zipboda-admin** | 운영 콘솔 | **본 문서 대상** |
| zipboda-api | 백엔드 API | 관리자 API 제공 |
| zipboda-web/app | 사용자 클라이언트 | 운영 데이터 소비처 |

## 7. 일정·공수 요약
- 총 공수 약 **23 PW**. **크리티컬 패스:** D0 기획 확정 → D2 청약 관리 → D4 운영 관리. D0(도출분 확정)이 선행 게이트로 전체 리스크의 핵심.
- 각 스테이지 관리자 API는 api가 동일 스테이지에 인도(대기 없음).

## 10. 검증 & 검토 반영 이력
1. Phase 검토 phase-review.rule.md 준수·기록. 2. CI 강제·회귀 누적. 3. 화면ID(ZB-A-*)·API ID가 대표 xlsx와 일치(미존재 0건). 4. A1~A4 준수(실연동 시 목 제거, API 갭 문서 등록). 5. 비기능: 보안(RBAC·감사)·성능·접근성(S7).

**검토 반영:** admin-Critical(화면기획 게이트·신청현황 API 갭 해소)·admin-Major(CRUD API 완성 반영)·admin-Minor(감사로그·자산 일정 정렬)·문서간 Critical(관리자 API 소비 시점 정렬)·C1~C5.
